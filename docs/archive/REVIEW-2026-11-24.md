## 4. Issues found

### 4.1 The reader read the seat file in the wrong place (found and fixed today)
When a second blend is loaded on top of the main reference, Blender doesn't update object positions until the scene
is refreshed. The reader read the seat file's arms and guides 30-250 mm out. So every pad joint built from your
seats was wrong (Arm 2B R by 36 mm), and so were the torso copies (the "11.8-30 mm off" from Nov 23).

**Not fully cleared:** the same bug affected **anything else read from a second file**: Turtle Ninja setup files and
Springles / Marta setup files, whenever they were passed. We need to check whether any earlier written run read a
second file. Run 26 read only the main reference, as far as I know. To confirm.

### 4.2 Non-Mar Fil arms are turned wrong
- **What happens:** Marta and Turtle Ninja arms are matched with the Mar Fil "Assault Arm Shoulder disc". The disc is
  round, so the turn comes from the part's own file. Marta's and Turtle Ninja's files are turned differently from Mar
  Fil's.
- **What the plan says:** PLAN.md (method, step 3) already says each maker's frame must be **converted by a reference
  part of that maker sat against Mar Fil**. That conversion was never built: the search uses the raw file turn for
  every maker.
- **One assumption to test:** whether one conversion per kit (or per maker) is enough depends on each maker's files
  sharing one frame. That's true for Springles (notes 114: 72 of 74 arms only moved, never turned). It's unknown for
  Marta (22 kits across 3 years) and Turtle Ninja.

### 4.3 The pad search can't fix the turn
- **What happens:** the pad cut is the whole inside of the pad, which is close to a bowl. A bowl matches itself at
  almost any turn, so the search slides it round (9-13°) or doesn't lock on at all.
- **Seen before:** notes 096-099 already found "round ones don't fix the turn" for round connectors.

### 4.4 Old and new fits are mixed in the library
- **Which methods:** the library holds fits from at least four methods:
  - Nov 15 no-cut fits
  - Nov 15 seat.py
  - Nov 19-20 cut writes
  - Nov 20 hand pad spots, now in the old pad frame
- **The effect:** a part can show a fit that looks fine and came from a method we've since dropped.
- **Agreed today:** drop the old ones.

### 4.5 Checks were run on the pipeline's own output
- **"Sure" counts:** these say a cut matched. They say nothing about whether the part sits where you would put it.
- **The proving sheets:** built from the same numbers, so they can't catch a reader that read your seats wrong.
- **Today's test was the first comparison against your actual seats.** It found 4.1 straight away.

The roll-backs, as they happened:

| When | What looked done | What undid it |
|---|---|---|
| Nov 15 | no-cut fits written (hands, packs, other makers) | Nov 16: you rejected the method; the fits are still in the library |
| Nov 19 | Mar Fil run 25 written | Nov 20: wrong fits came from the reference (parts moved after cutting); new reference, run 26 |

| Nov 23-24 | Marta shoulders "all sure" | Nov 24: wrong turn, because the plan's per-maker conversion was never built |

The pattern:
1. **"Sure" was treated as "right".** It only measures the shape match.
2. **No check against your placements.** Nothing compared the search's numbers with where you put the reference
   parts. That one check would have caught Nov 20's and Nov 23's problems on day one.
3. **Writing before the whole chain was proven.** Partial methods went into the library. Later changes then left
   old-frame data behind.
4. **Methods changed without the plan being updated.** The next session follows the old plan or loses the decision.
5. **Plan steps were skipped quietly.** The per-maker frame conversion and the spacer joint are both in the plan.
   Neither was built, and nothing said so.

## 6. Proposed ground rules (for you to agree or change)

1. **Gate 1, round trip.** Before any full run, every placement you made in the reference and seat files is rebuilt
   from the search's numbers alone. Each must come back within 0.1 mm and 1°. Anything that doesn't is a bug, fixed
   before going on.
2. **Gate 2, your eye.** A random set per maker (front, side, three-quarter) is rendered from the numbers alone. You
   say yes per maker.
3. **Gate 3, write.** Only after gates 1 and 2, for the whole chain: arm, pad and weapon together. The write is
   always new fits only, with a backup.
4. **One plan.** Every decision goes into `docs/PLAN.md` the same day, dated. If PLAN.md and a session disagree,
   PLAN.md wins until you change it.
5. **No silent gaps.** If a plan step isn't built, the run report says so in its first line.
6. **One list of input files.** PLAN.md names the files the runs read. Superseded files move to `_archive`.
